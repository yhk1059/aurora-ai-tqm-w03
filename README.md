# Aurora AI TQM — 품질 사건에서 공급 복구까지

품질 문제가 생겼을 때 **흩어진 부서 신호를 모아 회수 결정까지 올리고, 그 결정을 재공급 계획으로 이어 주는** 업무 시스템입니다. 가상 화장품 그룹 Aurora의 원료 로트 사건 `LOT-B-2602-P`를 처음부터 끝까지 처리합니다.

https://github.com/user-attachments/assets/be28c114-ff11-4176-b9ec-1a1da016e347

## 어떤 문제인가

같은 원료 로트로 만든 배치 2개의 불량률(11.9%, 11.6%)이 회수 기준 10%를 넘은 지 91일, 51일이 지났지만 회수 결정 기록이 없습니다. 데이터는 모두 있었습니다. 다만 신호가 부서마다 흩어져 있었습니다.

- 품질은 클레임을, 생산은 배치를, 물류는 출하를 따로 봅니다.
- 검사에서 보류된 배치가 출하됐고, 클레임 14건을 낸 고객은 출하 기록에 없습니다.
- 가동률이 97%라 재공급하면 마지막 고객은 21개월 뒤에야 받습니다. 영업은 핵심 고객을 먼저 달라고 합니다.

근본 원인은 **엇갈린 부서 신호를 모아 결정권자에게 올리는 책임과 절차가 없다**는 것입니다.

## 무엇을 하나

품질팀 사건 담당자가 사건 하나를 열고, 두 번의 결정을 거쳐 복구 계획을 확정합니다.

```
기준 초과 배치 발견 → 사건 열기 → 안건 상신 → [결정 1] 품질위원회: 회수 범위
                                                  ↓ 결과가 상태로 남음
     부서 회신 반영 → 재공급 계획 재계산 → [결정 2] SCM: 재공급 계획 승인
```

- **원료 로트 기반 영향 추적**: 클레임의 원료 로트에서 같은 로트로 만든 배치를 모두 묶습니다. 기준을 넘은 배치는 회수 대상, 합격 배치는 회수하지 않고 관찰 대상으로 둡니다. 왜 회수하지 않는지 근거가 남습니다.
- **결정이 작업을 만든다**: 위원회 결과에 따라 물류·생산·영업에 확인 작업이 생기고, 회신이 오면 상태와 계획이 바뀝니다.
- **다른 부서 영향**: 영업 임원이 핵심 고객 우선을 요청하면 계획이 다시 계산되고 SCM이 다시 승인해야 합니다. 복구가 12개월을 넘으면 생산에 능력 확보 검토를 요청합니다.
- **불리한 경우도 처리**: 위원회 거절, 출하처 확인 불가, 늦게 들어온 클레임도 같은 사건 안에서 다시 판단합니다.

## 사람·규칙·AI의 역할

| 누가 | 하는 일 |
|---|---|
| 규칙 | 불량률 계산, 회수 기준 판정, 작업 생성, 재공급 순서 계산 |
| 사람 | 안건 상신(담당자), 회수 범위 결정(품질위원회), 재공급 승인(SCM), 안내 대상 결정(영업) |
| AI (Claude) | 안건 요약 초안, 부서 회신 분류, 고객 안내문 초안. **판정하지 않고 상태를 바꾸지 않습니다** |

화면의 모든 값에는 출처가 붙습니다: 원본 데이터 / 계산으로 도출 / 가정 / 모의 입력. 결정과 부서 회신은 모의 입력이고, 그 뒤의 판정·작업·재계산은 실제로 작동합니다.

## 기술과 실행

React + Vite + Tailwind / FastAPI + SQLite / Claude API. 설계 문서는 [`w03_system/brain`](w03_system/brain)에 있습니다.

> 대회 원본 데이터(`01_참가자_배포용/04_원본데이터/`)는 이 저장소에 없습니다. 실행하려면 그 폴더를 저장소 루트에 두어야 합니다.

```bash
cp w03_system/.env.example w03_system/.env   # ANTHROPIC_API_KEY 입력
uv venv -p 3.14 w03_system/.venv && uv pip install -p w03_system/.venv -r w03_system/backend/requirements.txt
npm --prefix w03_system/frontend install && npm --prefix w03_system/frontend run build
w03_system/.venv/bin/uvicorn backend.api.main:app --app-dir w03_system --port 8000   # http://localhost:8000
```
