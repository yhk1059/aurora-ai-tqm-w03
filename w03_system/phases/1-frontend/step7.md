## 작업

남은 탭 2개를 만든다. 둘 다 읽기 전용이다.

### 기록 탭 `tabs/LogTab.tsx`

"무엇이, 누구에 의해, 어떤 규칙으로 바뀌었는지"를 처음부터 끝까지 다시 따라갈 수 있어야 한다.

**액션 기록** (`view.log.actions`, 순번순. 최신이 위/아래 전환 가능)

- 줄마다: 순번, 액션 이름(온톨로지 `actions`의 이름. 자동 처리는 기록된 이름 그대로), 실행자(역할 이름 또는 "시스템"), 적용일.
- 자동 처리(`actor`가 시스템)는 들여쓰고 "자동" 표시, 원인(`cause.rule`, `cause.reason`, 어느 사람 액션 뒤인지 `after_seq`)을 보인다.
- 펼치면: 입력(`inputs`) 이름-값 표, 변경 목록(대상 타입·ID · 필드 · **이전 → 이후** · 규칙).
- 연결된 AI 기록이 있으면(입력의 `ai_log_id`, 또는 AI 기록의 `action_seq`) 그 AI 기록으로 가는 링크(같은 탭 안 이동).
- 위에 간단한 거르기: 전체 / 사람 액션만 / 자동 처리만. 검색·정렬·페이지 나누기는 만들지 않는다.

**AI 기록** (`view.log.ai`)

- 줄마다: 순번, task(한국어 이름: 안건 요약 / 회신 분류 / 재검토 설명 / 안내 초안), 모델, 연결된 액션 순번, 성공/실패.
- 펼치면: 입력 전체와 출력 전체를 그대로(JSON은 들여쓴 `pre`, `text-xs font-mono`). 줄이지 않는다. 이유: 과제가 AI 입출력 기록을 요구한다.

사건이 없으면 "기록 없음".

### 온톨로지 탭 `tabs/OntologyTab.tsx`

`GET /api/ontology` 응답을 **정의 그대로** 표로 보인다. 이 탭은 "화면과 규칙이 이 정의 하나에서 나온다"를 보여주는 곳이다. 사건이 없어도 보인다.

| 구역 | 내용 |
|---|---|
| 객체 타입 | 타입마다: 이름, 저장/파생 구분, 속성 표(키·이름·관련 규칙), 상태가 있으면 상태 목록 |
| 관계 | 관계 유형, 출발 → 도착 타입, 확인 수준·수량을 갖는지 |
| 상태 전이 | 상태 기계마다: 초기 상태, 전이 목록(이전 → 이후). 표로 그린다 |
| 규칙 | R1~R12와 세부 규칙: 번호, 요약, 기준값과 **출처 배지**(예: `10%` `원본`, `90일` `가정 A-07`), 근거 참조 |
| 액션 | 이름, 실행 역할, 입력, 전제 조건, 효과, 관련 규칙, 만드는 작업 |
| 작업 유형 | 코드, 담당 부서, 대상, 허용 결과와 효과 |
| 자동 처리 | 이름, 규칙 |
| 역할·출처·확인 수준 | 목록과 근거 |

- 구역 사이는 탭 위쪽의 구역 링크로 이동한다.
- 화면에 정의를 다시 쓰지 않는다. 구역 제목과 열 이름 외의 글자는 전부 서버 응답에서 온다. 응답에 화면이 모르는 키가 있으면 버리지 말고 이름-값으로 그대로 보인다.

## 금지사항

- 온톨로지를 그래프 그림으로 그리지 마라. 이유: 정의는 표로 읽는 것이 정확하고, 연결망(사건 탭)과 헷갈린다.
- 기록을 지우거나 고치는 기능을 만들지 마라. 이유: 기록은 실행 증거다. 지우는 길은 초기화뿐이다.
- AI 입출력을 요약하거나 잘라서 보이지 마라. 이유: 전체가 남아 있어야 검증할 수 있다.
- 서버 코드(`w03_system/backend/`)를 고치지 마라. 이유: 이 step은 화면만 다룬다. 서버에 없는 값이 필요하면 `blocked`로 남겨라.
- `01_참가자_배포용/04_원본데이터/`의 파일을 수정하지 마라. 이유: 원본 데이터는 대회 규칙상 수정 금지다.
- 기존 테스트를 깨뜨리지 마라
