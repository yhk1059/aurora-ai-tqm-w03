### 확장 (A01 §4, A03 §1·§5)
- 필수 확장은 대표 업무의 **조회·계산·판단·상태 변경 중 하나 이상에 실제 반영**. **추가 전과 비교해 무엇이 달라지는지 실행 사례로** 보여줄 것. 아이디어·도식·설명만으로는 불충족
- 현업 경험뿐 아니라 연구·학습·개인 프로젝트 관점도 가능. **그 관점을 적용하는 이유와 조건**을 밝힐 것
- BPMN 재설계 가능. 원본에 없는 승인 절차는 **교육용 가정으로 정의하고 기존 권한과의 관계를 설명**
- 정보가 부족하면 **원본 도출 · 확인 요청 · 명시적 가정 · 합성** 중 선택하고 이유 설명. 합성은 선택 사항이며 안 해도 불리하지 않음. 미확인 정보는 **미확인 상태 + 다음 행동**으로 관리 가능
- 새 조건 시험 시 **기준 상황과 모의 상황을 나눠 비교**. 합성 결과는 "해당 가정 아래의 결과"로 표현
- **정보가 없는 경우**와 **원본 기록끼리 충돌하는 경우**를 구분
- 추가 확장은 **실제 작동 / 모의 처리 / 설계 단계**로 구분해 제출

### 필수 시연 세부 (A01 §5)
- 준비한 화면·결론을 순서대로 보여주는 것만으로는 실행 증거가 아님
- **정상**: 입력 → 데이터·문서 확인 → 계산·판단 → 근거와 대안 → 승인/후속 처리 → 결과·상태 기록
- **변경**: 주요 조건·가정이 달라지는 입력 → 기존 판단과 후속 계획 재검증. 불리·불확실 조건(공급 지연·수요 하락·**검사 보류** 등) 활용 가능. **결론이 유지되면 그 근거**를 보여줄 것
- **정보 부족 또는 승인 거절**: 추가 확인·보류·재상신·대안 검토 등 다음 행동. 변경 사례와 합쳐도 됨
- 한 건 이상에서 **필수 확장이 쓰이는 지점**과 **다른 부서 제약 때문에 대안·승인·계획·후속 처리가 달라지는 지점**을 보여줄 것
- 각 사례: 사용 데이터, **적용 시점**, 주요 계산·가정, AI·사람·도구 역할, **변경 전후 차이** 설명
- 모의 회신을 받은 뒤 **구현이 직접** 판단·계획·상태를 갱신하면 실제 반영 증거로 인정. 화면에 예상 결과만 적어 둔 것은 아님

### 제출할 내용 (A01 §6) — 형식은 구현 도구에 맞게 자유
1. **문제·전문성 확장 설명**: 사용자, 의사결정, 선택 이유, 원본과의 연결, 앞뒤 업무 연결, 필수 확장·부서 영향의 실제 반영
2. **업무모델과 데이터 설명**: 객체·관계·상태·규칙, AI·사람·도구 역할, 원본 범위, 공백 처리 이유, 추가 데이터·가정·제약과 검증
3. **실행 증거**: 세 사례의 입력, 처리 과정, 생성·갱신된 계획·작업·상태
4. **재현 방법**: 소스코드 또는 실행 가능한 프로젝트 접근, 설정, 대표 사례 재실행 절차
5. **추가 확장 목록**: 필요성, 판단 개선, 기존 업무와의 연결, 구현 상태, 증거

### 심사 방식 (A01 §7~8)
- **예선 = 제출 결과·실행 증거**, **본선 = 시연·조건 변경·질의응답**
- 본선의 새 조건·정보 정정·거절·**조건부 승인** 회신은 **선언한 구현 범위 안에서** 제시됨. 결론이 유지돼도 재검증 근거를 설명하면 됨
- 세계관 크기·합성 데이터 양·모의 성과 수치보다 **정보 정의의 이유, 업무 논리·제약의 타당성, 조건 변화에 따른 실제 판단·처리·검증**을 봄
- 원본 폴더에 남은 이전 대회의 3시간 제한·제출 방식은 적용하지 않음. 일정·제출처는 별도 운영 공지

### 제출 양식 구조 (A04) — 제출 화면 설계 설명 문항의 원본
1. **문제와 전문성 확장 요약**: 결과물 이름 / 선택한 사용자·의사결정 / 현재의 어려움 / 기업 운영 안에서의 연결 / 주업무의 시작과 종료 / 본인의 관심·전문성 / 필수 전문성 확장 / 영향받는 다른 부서의 목표·제약 / 다른 부서 영향의 실제 반영 / 확인할 개선 효과
2. **업무모델과 데이터 설명**: 핵심 객체 / 핵심 관계와 연결 기준 / 상태·적용 시점·담당자·승인권한 / 판단 규칙과 제약 / 업무모델이 조회~후속 작업을 연결하는 위치 / BPMN에서 바꾼 것과 이유 + 자료표(원본 자료 · 추가·도출 자료 · 필요하지만 없는 정보)
3. **대표 실행 사례**: 정상 / 변경 / 정보 부족·승인 거절 표 + AI 역할, 예상 효과 산정 방식, 확인된 효과 vs 추정 효과 구분, 확장·부서 영향 지점
4. **추가 확장 목록**: 내용·필요성 / 연결·구현 상태 / 증거
5. **실행·재현 방법**: 위치, 도구·버전·의존성, 데이터 불러오기, 대표 사례 입력·순서, 변경·모의 회신 입력 방법, 결과 확인 위치, 초기화 항목
6. **제출 전 자기점검**: 15개 항목 (사용자·결정 설명, 상태 갱신 연결, BI에서 끝나지 않음, 확장·부서 영향 실제 반영, BPMN 변경 이유, AI 입출력 사용, 세 사례 실행, 원본·주장·가정·모의 구분, 공백 처리 이유, A05 기준, 실제·모의·설계 구분, 실행 절차 등)

### 데이터 관리 규칙 (A05 §1~3)
- 원본 폴더 보존. **정제·매핑·수식·확장 데이터는 별도 폴더**에 두고 **원본 행 또는 파일까지 추적** 가능하게
- 원본 불일치를 발견하면 적용 범위와 처리 방식을 설명 (모든 오류 복구는 필수 아님)
- 사건의 **발생일과 적용일을 별도로 기록**
- 전체 배경은 2024-01~2026-06이지만 **파일별 실제 관찰기간은 다름**. 전망·계약 기한은 기준일 이후도 포함
- CSV: UTF-8, 첫 행 헤더, `|` 구분자
- 재고·자금·손익 계열은 회사 전체 규모, 마케팅 주문·쿠폰·반품·광고비 등은 **대표 표본** — 표본을 전사 금액과 합산 금지
- 추가 행에는 **식별자·적용 시점·원본 연결·생성 이유**를 남길 것 (A05 §6)
- 원본 제약(독점 공급·능력·계약·승인)을 바꾸는 가정은 기본 사실로 덮어쓰지 말고 **명시적인 대안 시나리오**로 분리
- 예선 제출 시 사용 자료·가정·업무 설계의 **버전 기록**. 본선은 그 범위를 기준으로 사건 적용
