# w03-task — W03 업무 안내 정리

> 출처: `01_참가자_배포용/세계관_BPMN/W03.html` (AX 인재전쟁 v1.5, 2026-10-29), 흐름도 `W03.bpmn` / `W03.svg`, `A06_세계관별_BPMN_도식집.pdf` 3쪽(같은 내용 + "도식의 사용 범위"), 관련 맥락은 `A02.html` §5·`A05.html`
> 이 파일은 **주최 측 안내 내용만** 담는다. 어떤 시나리오·확장을 고를지는 아직 정하지 않았다 (`../status.md`).

## 핵심 질문
품질 판정과 고객 공급 일정이 분리돼 있을 때, **어떤 사실을 연결해야 과잉 대응과 대응 지연을 줄일 수 있는가?**

## 현재 업무 흐름 (BPMN)

| 순서 | 레인(담당) | 단계 |
|---|---|---|
| 0 | 품질 | 업무 발생 (시작) |
| 1 | 품질 | 클레임 접수 |
| 2 | 품질 | 배치·검사자료 취합 |
| 3 | 품질 | 회수 안건 작성 |
| ◇ | **품질위원회** | 위원회가 회수를 의결했는가? |
| 4 (예) | 품질 | 의결 범위 담당자 전달 |
| 5 (예) | 생산·SCM | 공급 영향·일정 부서별 확인 |
| 6 (예) | 영업·고객대응 | 고객 안내·후속 회신 기록 → 종료 "후속 회신 기록" |
| (아니오) | 품질위원회 | 종료 "조사·재검토" |

- 레인 4개: 품질 / 생산·SCM / 영업·고객대응 / 품질위원회
- 승인 분기는 사람이 수행한 **별도 승인 절차의 결과**이며 세부 승인 단계는 생략됨
- **보류·재검토 종료 = 이번 검토 회차의 종료**일 뿐, 후속 확인 의무의 종료가 아님
- 그림의 관계가 원본 파일의 모든 연결키 제공을 뜻하지 않음 → **원본에서 확인한 관계와 추가한 매핑·가정을 구분**할 것

## 도식의 사용 범위 (A06)
- 현재 흐름의 역할·순서·확인 방법은 **재설계해도 됨**. 단 원본 사실·제약·권한을 존중하고 **변경 이유를 설명**할 것
- 관계도만이 아니라 **사건에 따른 조회·상태 변화·승인·후속 처리**를 구현할 것
- 제공된 흐름을 비판·수정할 수 있으며, 개선한 단계가 **어떤 객체를 조회하고 어떤 상태를 바꾸는지** 설명할 것 (A05 §7)

## 기존 자료의 단초 (원본 규칙)
- 회수 판정 단위 = **생산 배치**. 규격이탈 **확정 불량률 10% 이상**이 회수 대상 기준
- 회수 실행 = **품질위원회 의결**. 원인 규명 완료와 회수 요건 충족은 **별도로** 다룸
- **예비검사 보류 ≠ 확정 불량**. 미확정 언론 보도만으로 전면 회수를 판단하지 않음
- 배치·로트·품질 클레임·출하 연결 자료는 있으나 **공급 복구 절차 전체는 제공되지 않음**

## 주최 측 교육용 가정 (원본 아님 — [교육용 가정])
- 품질팀이 클레임·배치 자료를 모아 위원회에 제출하고, 의결 후 영업·생산이 후속 일정을 **수작업으로** 확인하는 흐름
- '회수 의결'이 없는 경로는 조사 계속 상태로 끝남. 단, **기준 충족 건의 회수를 인과관계 미확정만으로 지연해도 된다는 뜻은 아님**
- [범위] 공급 복구 수량·일정·담당자의 구체 규칙은 **참가자가 새로 정의할 영역**. 도식은 복구 해법을 지정하지 않음. 아래 보완 항목은 선택 예시이고, 필수 확장·다른 부서 영향 기준은 A01을 따름

## 미해결 지점 (원본의 공백)
- 품질 출하 SBL ↔ 재무 출하 SH를 일대일 연결하는 **검증된 매핑 없음**
- 회수 대상 제품의 실제 **재고 위치·고객 보유량·회수 실적** 자료 없음
- **대체 생산·재공급 일정**과 **품질 재승인 이력** 없음

## 확장할 때 생각할 질문 (주최 측 제시)
1. **회수 범위 확인**과 **공급 복구** 중 어느 병목에 집중할 것인가?
2. 출하 식별자가 연결되지 않는 경우 **어디까지 확정하고 무엇을 보류**할 것인가?
3. 품질 판정이 **정정됐을 때** 어떤 부서의 기존 기록을 다시 확인해야 하는가?

## 보완할 수 있는 데이터 (주최 측 예시 — 만들면 [가정]/[모의] 표시)
- 검증된 배치-출하-납품처 매핑
- 품질위원회 의결·정정 이력과 회수 접수 기록
- 재공급 요청·생산 가능일·품질 확인 회신

## 다른 안내 문서의 W03 관련 내용
**A03 확장 가이드 §4 — 세계관 탐색 질문**
- "품질 위기와 공급 복구: **어디까지 조치하고 어떤 조건에서 다시 공급할까?**"

**A02 기업 시나리오 §5 "품질 문제가 생기면 어디까지 영향을 받는가?"**
- 더마 라인에서 클레임 발생, 일부 배치는 확정 문제. 원인 조사는 계속 중
- 배치 단위 회수 기준과 품질위원회 승인 절차가 있음. **외부 기사와 검사 결과는 성격이 다른 정보**
- 품질 판단 이후에도 남는 일: 어떤 **재고·출하**가 영향을 받는지, 누구에게 **확인·조치를 요청**할지, **정상 상품을 어떻게 공급**할지, **어떤 조건에서 판매를 재개**할지
- 질문: 원료·배치·상품·고객의 관계를 어느 범위까지 확인할 수 있고, 어떤 연결을 추가로 설계해야 하는가?

**A05 데이터 이용 기준 중 W03 관련**
- 품질 회수 규칙: 불량 확정 **과** 배치 불량률 10% 이상을 **함께** 확인 → 품질위원회 의결로 실행. **원인 조사와 회수 실행의 승인 절차를 구분**
- SBL(`shipment_batch_link_cv`)과 SH(`sales_shipments_cv`)는 직접 연결되지 않음 → 매핑을 만들면 확인된 관계인지 합성 관계인지 명시
- 원료 입고·투입: 일부 투입일이 입고일보다 빠르고 로트별 누적 투입량이 입고량을 초과 → 물량 보존·생산 이력 완전 재현은 요구하지 않음
- SKU·제품군·생산 배치·원료 로트·공장·생산라인은 **서로 다른 집계 수준**. 비슷한 코드만으로 일대일 대응을 가정하지 않음
- 단위: 금액 원(VAT 제외), 제품 수량 EA, 원료 kg. `NONE`은 0과 다른 "해당 없음" 코드. 업무 달력은 월~금 영업일, 공휴일 없음
- 먼저 볼 위치(조달과 품질): `01_corevia/procurement`, `01_corevia/quality`, `01_corevia/production`
