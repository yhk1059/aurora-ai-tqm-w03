## 디자인 원칙
1. **결정을 내리는 도구처럼 보인다.** 한 화면에서 "지금 상태 → 근거 → 내가 할 수 있는 일"이 위에서 아래로 읽힌다. 마케팅 페이지가 아니라 매일 쓰는 업무 화면이다.
2. **모든 숫자와 관계에 출처가 붙는다.** 원본 / 도출 / 가정 / 모의 / 시스템을 배지로 구분한다 (완료 조건 5).
3. **바뀐 것은 반드시 보인다.** 액션을 실행하면 "방금 바뀐 것"에 이전 → 이후와 적용된 규칙이 나온다.

## AI 슬롭 안티패턴 — 하지 마라
| 금지 사항 | 이유 |
|-----------|------|
| backdrop-filter: blur() | glass morphism은 AI 템플릿의 가장 흔한 징후 |
| gradient-text (배경 그라데이션 텍스트) | AI가 만든 SaaS 랜딩의 1번 특징 |
| "Powered by AI" 배지 | 기능이 아니라 장식. 사용자에게 가치 없음 |
| box-shadow 글로우 애니메이션 | 네온 글로우 = AI 슬롭 |
| 색을 장식으로 쓰기 | 색은 세 가지 뜻으로만 쓴다: 행동(남색), AI가 쓴 것(보라), 상태(빨강·주황·하늘색·초록·회색). 뜻 없는 색 면·그라데이션은 쓰지 않는다 (v10에서 "보라/인디고 브랜드 색상 금지"를 이 줄로 바꿨다) |
| 모든 카드에 동일한 rounded-2xl | 균일한 둥근 모서리는 템플릿 느낌 |
| 배경 gradient orb (blur-3xl 원형) | 모든 AI 랜딩 페이지에 있는 장식 |
| 판단에 쓰이지 않는 차트 | 과제가 "대시보드·차트는 미완성"이라고 명시한다. 숫자는 판정 카드와 표로 보인다 |
| AI 출력을 사람 입력과 구분 없이 표시 | AI가 만든 요약·분류·초안에는 항상 "AI 초안" 표시와 검토 후 사용하는 버튼을 둔다 (R12) |
| 색만으로 상태 구분 | 상태는 항상 글자와 함께 표시한다 |
| 어두운 테마, 테마 전환 | 밝은 테마 하나만 만든다 |

## 색상
색은 세 가지 뜻으로만 쓴다 (v10): **행동 색**(남색), **AI 색**(보라), **상태 색**(아래 표). v9까지는 "브랜드 색은 없다, 색은 상태에만 쓴다"였다. 화면이 단조롭고 가장 중요한 버튼이 눈에 띄지 않아 바꿨다.

### 행동 색·AI 색 (v10)
| 뜻 | 쓰는 곳 | 값 |
|------|------|------|
| 행동 색 (남색): 사람이 누르는 것, 지금 고른 것 | 주 버튼 | `bg-indigo-500 text-white hover:bg-indigo-600` |
| | 선택된 탭·필터·버전·예시 칩·결정 선택 버튼, 연결망에서 고른 노드 | `border-indigo-600` + `bg-indigo-50` (탭은 "레이아웃"의 탭 모양, v12) |
| | 진행 단계의 지나온 길과 지금 위치 | `bg-indigo-500` (지금 위치는 `ring-4 ring-indigo-100`) |
| | 열린 폼 박스 | 테두리 `border-indigo-300`, 머리·아래 띠 `bg-indigo-50` |
| | 상단 바 | `bg-indigo-100 border-b border-indigo-200`, 앱 이름 `text-indigo-900` |
| | 입력 필드·버튼 포커스 | `indigo-600` |
| AI 색 (보라): AI가 쓴 것, AI에게 요청하는 것 | AI 요청 버튼 | `border-violet-300 bg-violet-50 text-violet-800 hover:bg-violet-100` + 반짝임 아이콘 |
| | AI 초안 블록 | `border-dashed border-violet-300 bg-violet-50`, `AI 초안` 라벨 `text-violet-800` |

- 채운 색(흰 글자)은 주 버튼과 탭의 할 일·결정 배지(v12)에만 쓴다. 나머지는 옅은 배경 + 같은 계열의 진한 글자다.
- 남색은 상태에 쓰지 않는다. "기다리는 중" 상태가 파랑이면 행동 색과 구분되지 않아 하늘색으로 옮겼다.
- 옅은 색 배경 위의 작은 글자는 `text-neutral-600`보다 옅게 쓰지 않는다.

### 배경
| 용도 | 값 |
|------|------|
| 페이지 | `bg-neutral-50` |
| 카드 | `bg-white` |
| 표 머리, 눌린 영역 | `bg-neutral-100` |
| 방금 바뀐 항목 강조 (1초) | `bg-amber-50` |

### 텍스트
| 용도 | 값 |
|------|------|
| 주 텍스트 | `text-neutral-900` |
| 본문 | `text-neutral-700` |
| 보조 | `text-neutral-500` |
| 비활성, 빈 값 표시(—), 화살표(→) | `text-neutral-400` |

읽어야 하는 글자는 `text-neutral-500`보다 옅게 쓰지 않는다. `bg-neutral-100` 위(표 머리)에서는 `text-neutral-600`을 쓴다 (v3, 본문 대비 4.5:1).

### 데이터/시맨틱 색상
| 의미 | 쓰는 상태 | 값 (글자 / 배경 / 테두리) |
|------|------|------|
| 빨강: 기준 초과, 회수 | 기준초과, 회수진행, 부분회수 | `text-red-800` / `bg-red-100` / `border-red-300` |
| 주황: 경고, 확인 안 됨 | 미확인, 보류 출하 경고, 보류 로트 투입, 원본 기록 충돌, 미확정 클레임 | `text-amber-800` / `bg-amber-100` / `border-amber-300` |
| 하늘색: 사람의 응답을 기다리는 중 | 상신중, 확인요청중, 조사계속, 계획 초안, 작업 열림 | `text-sky-800` / `bg-sky-100` / `border-sky-300` |
| 초록: 확인됨, 확정됨 | 확인, 회신확인, 계획 확정, 작업 완료 | `text-emerald-800` / `bg-emerald-100` / `border-emerald-300` |
| 회색: 문제 없음, 종료 | 관찰, 관찰해제, 영향없음, 클레임 기각, 계획 기각·대체됨 | `text-neutral-600` / `bg-neutral-100` / `border-neutral-200` |

상태 → 색 매핑은 화면 코드에 한 곳(상태 배지 컴포넌트)에만 둔다.

배지·건수 칸처럼 배경을 칠하는 곳은 위 값(배경 100, 글자 800)을 쓴다 (v10, v9까지는 배경 50·글자 700). 흰 배경 위의 색 글자(경고 줄, 불량률 숫자)와 경고 구역 상자(`bg-amber-50`)는 그대로 700·50이다.

## 컴포넌트
### 카드
```
박스:        rounded-lg bg-white border-2 border-neutral-300 shadow-lg/20 p-4
박스 키워드: px-0.5 text-base font-bold text-neutral-900  (박스 위 바깥, 박스와 간격 gap-2)
```
- 박스 키워드 (v13): 박스가 무엇인지는 테두리 밖 왼쪽 위의 키워드로 읽힌다. 박스 안에는 제목을 두지 않는다. 건수·보조 설명은 키워드 옆에 `text-xs font-normal text-neutral-500`으로 붙인다(`작업 열림 4 / 전체 6`, `배치 4개`, `최근 기록 16건`). 사건 요약 띠의 키워드는 `사건 현황`이다. 배치 카드는 카드마다가 아니라 묶음에 `배치 N개`를 한 번만 붙이고, 묶음 안 카드 사이는 `space-y-2`다.
- 테두리 굵기 (v13): 큰 박스(카드, 사건 요약 띠, 배치 카드)는 2px이다. 색은 `border-neutral-300`, 기준 초과 배치 카드는 `border-red-300`이다. 박스 안의 작은 박스(건수 칸, 버튼, 입력, 폼 박스, AI 초안 블록, 표)와 온톨로지 탭의 접는 구역 줄, 주황 경고 띠는 1px 그대로다.
- 입체감 (v13): 큰 박스에는 그림자(`shadow-lg/20`, 넓게 퍼지는 그림자를 진하기 20%로)를 깔아 바닥에서 살짝 떠 보이게 한다. 그림자는 움직이지 않고(hover·등장 효과 없음) 색을 넣지 않는다. 안티패턴의 "글로우 애니메이션"과는 다르다. 박스 안의 작은 박스에는 그림자를 쓰지 않는다.

### 버튼
```
Primary (액션 실행. 사건 탭에서는 요약 띠의 판정 버튼과 열린 폼의 실행 버튼): rounded-md bg-indigo-500 text-white px-3 h-8 text-sm hover:bg-indigo-600
Secondary (보조 액션):            rounded-md border border-neutral-300 bg-white px-3 h-8 text-sm hover:bg-neutral-50
Ai (AI 요청, v10):                rounded-md border border-violet-300 bg-violet-50 px-3 h-8 text-sm text-violet-800 hover:bg-violet-100
Text:                             text-sm text-neutral-500 hover:text-neutral-900
```
- 버튼은 서버가 준 "가능한 액션"만 그린다. 지금 역할로 실행할 수 없는 액션은 보이지 않는다.
- 키보드로 옮겨 간 버튼·링크에는 테두리를 그린다: `outline: 2px solid indigo-600; outline-offset: 2px` (`:focus-visible`, `index.css` 한 곳). 입력 필드는 테두리 색으로 표시한다 (v3).
- 되돌릴 수 없는 결정(위원회 결정, SCM 결정, 초기화)은 누르면 확인 창에서 입력(사유·근거)을 받고 실행한다. 확인 창은 화면 가운데에 띄우고(내용은 좌측 정렬), 결정의 결과는 드롭다운이 아니라 큰 선택 버튼으로 고른다 (v2).
- 결정 창 (v4): ① 창이 화면을 가리므로 판단 근거를 창 안 맨 위에 다시 보인다(위원회 결정: 대상 배치의 불량률·수량·기준 초과일·경고 수, 출하처 미확인 고객, 상신된 안건 요약). ② 선택 버튼마다 고르면 일어나는 일을 한 줄로 적는다(문구는 액션 정의의 `choice_effects`). ③ 아래 줄은 왼쪽에 주의 문구, 오른쪽에 `취소` → 실행 순서. 실행 버튼 이름은 고른 결과를 담는다(`승인 결정 실행`). ④ 모의 입력 예시는 입력 칸 아래에 둔다.
- 결정 창 (v5): 선택 버튼이 창의 첫 화면에 들어와야 한다(1440×900에서 스크롤 없음). ① 위원회 결정 창의 안건 요약은 첫 줄(요지)만 보이고, 나머지는 `요약 전문 보기 (N자)`로 편다. ② 재공급 계획 결정 창에도 판단 근거를 둔다: 재공급 순서와 마지막 완료 예상 월, 이전 버전 대비 바뀐 고객만, 출고 조건 충족 여부, 영업 임원 확인 대기. 값은 서버가 계산한 계획에서 고른다.
- 재공급 계획 결정 창의 출하 경위 (R11-1): 사건에 출하 경위 확인 작업이 있으면 판단 근거에 `출하 경위` 줄을 더한다. ① 열림: 주황 `확인 대기` + 기한(연장됐으면 `연장됨 (처음 기한 …)`, 작업 목록과 같은 계산). ② "확인 불가" 회신으로 열려 있음: ①에 더해 마지막 회신 문장 + `모의` 배지. ③ 완료: 초록 `확인됨` + 회신 문장 + 회신 적용일 + `모의` 배지. 대상 항목의 `approve_reason_required`가 참이면 `승인`을 고르고 근거가 비었을 때 실행 버튼을 끄고 '출하 경위 확인이 끝나지 않아, 승인하려면 근거를 적어야 합니다.'를 보인다(거절의 사유 필수와 같은 방식, 최종 확인은 서버). 규칙 번호·가정 ID는 툴팁에 둔다.
- 박스 크기 (v7): 박스는 내용 크기에 맞춘다. 내용이 작은데 같은 너비로 늘리거나 줄을 다 쓰게 하지 않는다. ① 요약 띠 건수 칸은 같은 너비 4칸이 아니라 내용 너비의 칸을 한 줄에 나란히 둔다(이름과 숫자를 한 줄에). ② 인라인 폼 박스는 내용 너비에 맞춘다(최소 32rem). AI 초안처럼 내용이 넓을 때만 줄을 다 쓴다. ③ 인라인 폼에서 짧은 입력(선택·숫자·날짜·고정 값)이 이어지면 한 줄에 나란히 두고, `적용일`은 실행 버튼과 같은 줄에 둔다. 글 입력·체크 목록·AI 자리가 붙은 입력은 줄을 다 쓴다. ④ 안건 상신 폼의 `AI로 안건 요약`과 `안건 요약 직접 쓰기`는 한 줄에 둔다. 결정 창은 그대로다.
- 요약 띠의 폼 자리 (v9): 사건 요약 띠는 두 칸이다. 왼쪽 칸에 상황 문장·진행 단계·건수·버튼, 오른쪽 칸에 버튼을 눌러 연 폼(제목 = 버튼 이름)이 온다. 폼을 열어도 띠 높이는 그대로다. 폼은 한 번에 하나만 열린다(다른 버튼을 누르면 바뀐다). 폼이 없으면 오른쪽 칸은 비어 있다. AI 안건 요약 초안이 나오면 글이 길어 그때만 폼이 아래 줄 전체를 쓴다. 화면이 좁아 오른쪽 칸이 26rem보다 좁아지면 폼은 아래로 내려간다. AI 안건 요약 초안의 열 수는 화면 너비가 아니라 초안이 놓인 칸의 너비로 정한다. 결정 창은 그대로 가운데 창이다.
- 요약 띠의 폼 박스 (v10): 오른쪽 칸에 열리는 폼은 세 층이다. ① 머리 띠(`bg-indigo-50`): 아이콘(20px) + 제목 + 오른쪽에 단계 이동. 안건 상신은 `품질위원회에 안건 상신`, `기준 초과 확인 → 위원회 판정`. ② 입력. 안건 상신의 배치는 체크 목록이 아니라 카드로 고른다(배치 번호, 미상신 일수, 불량률. 값은 배치 카드와 같은 서버 계산값). 입력 설명은 이름 옆에 잇는다. ③ 아래 띠(`bg-indigo-50`): 왼쪽에 `실행하면` + 생기는 일, 오른쪽에 적용일 → 큰 실행 버튼(`h-10`) → 취소. 폼을 열어도 띠 높이는 그대로다(v9). 작업 회신·클레임 판정처럼 목록 안에 열리는 폼은 테두리만 `border-indigo-300`으로 둔다.
- 카드 안 배치 (v8): 카드 안의 빈자리를 먼저 쓰고, 그래도 남으면 줄 수를 줄인다. ① 배치 카드: 근거 줄과 경고를 불량률 숫자 오른쪽에 두고, `근거·출처 보기`는 제목 줄 오른쪽에 둔다. ② 작업 목록: 작업 한 건은 한 줄이다(번호·유형·상태 → 담당·기한 → 대상 → 오른쪽 끝 `회신 입력`). 칸이 좁으면 줄이 바뀐다. 회신 내용·AI 초안·회신 폼은 그 줄 아래에 편다. ③ 재공급 계획 탭: 결정 카드(왼쪽 2/3)와 버전 카드(오른쪽 1/3)를 나란히 둔다. 출고 조건 카드의 항목 4개(공급 배치·원료 로트·QC 결과·월 여유 능력)는 한 줄에 나란히 둔다.
- 액션 폼 (v5): ① `적용일`은 폼 맨 아래 한 줄(이름 + 날짜 칸)로 두고, 설명은 툴팁으로 돌린다. ② 모의 입력 예시 줄의 이름은 `시연용 예시`다. 출처 배지는 줄에 한 번만 붙이고, 칩에는 예시 이름만 쓴다(유리·불리는 툴팁). ③ 폼에 내부 값 이름을 쓰지 않는다. AI 초안을 쓴 폼에는 "AI 기록 #N의 초안을 사용함"이라고 적는다.

### AI 초안 블록
```
rounded-lg border border-dashed border-violet-300 bg-violet-50 p-4  + 머리에 "AI 초안" 라벨(보라, 반짝임 아이콘), 아래에 검토 후 쓰는 버튼
```
- 본문 폭은 `max-w-4xl`로 묶는다 (한 줄 약 64자).
- **안건 요약 초안 (2026-11-14, 같은 날 구역 색 적용):** 위에서부터 요지 → 쟁점 → 배치 수치 표 → 대안 3칸 → 확인 안 된 것 → `근거 N개 보기`. 구역마다 색 라벨로 정보의 종류를 드러낸다. 색의 뜻은 "데이터/시맨틱 색상" 표와 같다.
  - 요지: 흰 카드, 보라 `요지` 라벨(`bg-violet-700 text-white`), 문장은 `text-lg font-semibold`.
  - 쟁점(최대 3개): 회색 라벨 `쟁점 N`, 번호 붙인 줄. 글 안의 배치·로트·고객 ID는 회색 칩(`font-mono`)으로 그린다.
  - 배치 수치 표: 기준 초과 배치가 있으면 빨간 라벨 `기준 초과 배치 N`과 빨간 테두리. `미상신 N일`은 빨간 굵은 글자, 경고 건수는 주황 배지.
  - 대안 3칸(`grid sm:grid-cols-3`, 대안마다 영향 최대 2개): 칸 머리에 색과 `→ 결정 뒤 배치 상태` 배지. 전면 회수 = 빨강(`회수진행`), 부분 회수 = 옅은 빨강(`부분회수`), 조사계속 = 하늘색(`조사계속`).
  - 확인 안 된 것(최대 4개, AI 출력 칸 이름은 `uncertainties`): 주황 구역, 경고 아이콘, 2칸 카드. ID는 주황 칩.
  - 근거: 접힌 채로 시작. 버튼 옆에 출처별 개수(`원본 2`, `시스템 3`), 펼치면 줄마다 출처 배지.
- `이 내용 사용`(안건 요약)을 누르면 큰 편집 창(`안건 요약 확인·수정`, 높이 60vh)이 뜬다. 창에서 고친 뒤 바로 `안건 상신 실행`을 누르거나, `취소`로 창만 닫는다. 폼에는 작은 입력 칸이 없다. 대신 `안건 요약 직접 쓰기`/`고치기` 버튼과 `작성됨 · N자`가 보인다 (2026-11-15).
- 배치 수치 표는 AI 글이 아니라 화면이 시스템 값으로 그린다. 표 위에 "배치 수치 · 시스템 계산값 (AI가 쓴 글이 아닙니다)"를 적어 AI 글과 구분한다. 위원회 결정 창의 판단 근거와 같은 줄 모양을 쓴다.

## 레이아웃
- 전체 너비: `max-w-7xl`, 좌측 정렬 기본. 중앙 정렬 금지.
- 간격: 카드 사이 `gap-4`, 카드 안 `space-y-3`.

**상단 바 (항상 보임):** 사건 ID · 사건 상태 · 기점 로트 │ 현재 적용일 · 역할 선택 · 초기화

**탭 4개**

탭 모양 (v12): 탭마다 아이콘(18px) + 이름(`text-[15px]`) + 배지. 높이 `h-11`. 선택된 탭은 `bg-indigo-50` + 굵은 글자(`font-semibold text-indigo-900`) + 밑줄 3px(`border-indigo-500`), 나머지는 `text-neutral-600`이다. 배지는 서버가 준 뷰에서만 센다: `사건` = `할 일 N`(이 역할이 지금 할 수 있는 판정 1 + 회신 입력 건수), `재공급 계획` = `결정 N`(결정할 수 있는 계획 수), `기록` = 액션 기록 수. 할 일·결정 배지는 행동 색으로 채우고(`bg-indigo-500 text-white`) 건수 배지는 회색이다. 0이면 배지를 그리지 않는다. 사건이 없으면 배지가 없다.

| 탭 | 내용 |
|---|---|
| 사건 | 맨 위: 사건 요약 띠(사건 상태, 상황 한 문장, 이 역할이 지금 할 일, 진행 단계, 건수 4개, 판정·새 입력 액션). 본문은 사건 상태에 따라 바뀐다 (v6, 아래 "사건 탭 본문"). **판정 전**(`열림`·`판정중`·`관찰중`): 왼쪽(2/3) 배치 판정 카드(기준 초과 배치 먼저: 판정 상태, 불량률과 기준선 막대, 근거 줄, 경고, 클레임. 기준 미달이고 미확정 클레임이 없는 배치는 한 줄로 접음) → 연결망(접힌 채 시작). 오른쪽(1/3) 방금 바뀐 것 → 작업 목록 → 최근 기록. **작업 단계**(`회수진행`·`복구계획확정`): 왼쪽(2/3) 작업 목록 → 배치 카드(한 줄로 접음) → 연결망. 오른쪽(1/3) 방금 바뀐 것 → 최근 기록 |
| 재공급 계획 | 위에서 아래로 (v6, v8): 결정 카드(이 버전이 무엇을 바꾸는지 한 문장, 마지막 완료 예상 월, 출고 조건 충족 여부, 이 버전의 결정, `결정 입력` 버튼)와 그 오른쪽의 버전 카드 → 영업 임원 확인 대기 주황 띠 → 출하 경위 확인 대기 주황 띠(서버 경고 `open_hold_shipment_check`가 있을 때. `출하 경위 확인 대기 N건` + 'QC 보류 배치가 출하된 경위가 아직 확인되지 않았습니다. 승인하려면 근거를 적어야 합니다.', 규칙 R11-1·가정 A-18은 툴팁) → 고객별 순위·수량·예상 월·수량 근거 표와 이전 버전 비교 → 출고 조건 카드. 비교 표에는 바뀐 줄(새로 추가·앞당김·지연)만 올리고, 그대로인 고객은 "변화 없음 N곳 + 고객 ID" 한 줄로 묶는다. 이전 버전이 없으면 표를 전체 너비로 쓰고 완료 예상 월 막대를 붙인다. 모든 줄의 출처나 우선순위 이유가 같으면 열을 없애고 표 아래에 한 번만 적는다 |
| 기록 | 액션 기록 전체(실행자, 적용일, 이전 → 이후, 원인 규칙)와 AI 입출력 전체. `전체` 보기에서는 자동 처리 줄을 그것을 일으킨 사람 액션 아래에 접어 둔다("이 액션 뒤 자동 처리 N건 보기"). `자동 처리만` 필터에서는 모두 펼쳐 보인다 (v3) |
| 온톨로지 | 객체 타입, 속성, 관계, 액션, 규칙 기준값과 출처를 정의 그대로 표시. 9개 구역은 접힌 채로 시작하고 제목 줄에 정의 개수만 보인다. `모두 펼치기`가 있다 (v3) |

- 사건 요약 띠 (v4): ① 상황 한 문장은 사건 상태에 따라 바뀐다(기준 초과 → 위원회 판정 중 → 회수 중 → 재공급 계획 확정). ② 문장 아래에 진행 단계 4개(기준 초과 확인 → 위원회 판정 → 회수 → 재공급 계획 확정)를 한 줄로 보인다. 지난 단계는 체크, 지금 단계는 채운 점과 굵은 글자, 남은 단계는 빈 점. 주 경로에서 갈라진 경우(거절 뒤 조사, 조건부 승인)는 지금 단계 옆에 주황 보조 글자로 적는다. 사건 상태가 `관찰중`이면 단계를 그리지 않는다.
- 사건 탭 본문 (v6): 화면은 그 단계에서 담당자가 정할 것을 가장 크게 보인다.
  - 작업 단계에서는 판정이 끝났으므로 기준 초과 배치도 한 줄(배치 ID, 상태, 불량률, `기준 초과`, 경고 건수)로 접는다. 미확정 클레임이 있는 배치는 판정할 것이 있어 펼쳐 둔다. 접힌 배치가 바뀌어도 펼치지 않고 배경 강조만 한다(판정 전 단계에서는 바뀐 배치를 펼친다).
  - 요약 띠의 "이 역할이 지금 할 일"은 서버가 준 가능한 액션에서 하나만 고른다: 판정 → 재공급 계획 결정(`재공급 계획 탭`) → 회신 입력 N건과 가장 이른 기한. 할 수 있는 것이 없으면 "열린 작업 N건의 회신을 기다리는 중".
  - 요약 띠 첫 칸은 판정 전에는 `기준 초과 배치`(빨강), 작업 단계에서는 `회수 중 배치`(회색)다.
  - 배치 카드: 미상신 경고가 기준 초과일과 경과 일수를 말하므로, 그 경고가 있으면 `기준 초과일`·`미상신 경과` 근거 줄은 그리지 않는다.
  - 연결망은 접힌 채 시작한다. 접힌 줄에 "원료 로트 N개 → 배치 N개 → 고객 N곳"과 출하처 미확인 고객을 적고, `연결망 펼치기`로 편다.
- 작업 목록 (v4): 열린 작업의 기한이 현재 적용일보다 앞이면 `기한 지남`(빨강), 기한이 연장된 적이 있으면 `연장됨 (처음 기한 …)`(주황)을 기한 옆에 적는다. 처음 기한은 액션 기록의 기한 변경에서 읽는다.
- 작업 목록 (v5): 작업 번호는 폼·기록과 같은 번호(`T-004`)를 쓴다. 유형 코드(`T-05`)는 화면에 쓰지 않는다.
- 방금 바뀐 것 (v5): 요약은 결과만 적는다. ① 제목 줄에 고른 결과를 붙인다(`위원회 결정 입력 · 승인`, `회신 반영 · 출하 확인`). ② 같은 대상의 연속 변화는 처음 → 끝으로 합치고(`열림 → 완료`), 같은 변화를 겪은 대상은 한 줄로 묶는다. ③ 출하처 확인 수준 변화와 새로 생긴 작업(유형별 개수)·재공급 계획을 함께 적는다. ④ 요약할 것이 없으면 "판정·작업·계획의 상태는 그대로입니다 (기록만 남음)"이라고 적는다. 전체 변경과 규칙 번호는 `자세히`에 그대로 둔다.
- 사건이 없을 때(S0) (v14): 화면 너비를 채운다. 별도 입력 카드와 배치 드롭다운은 없다. 배치는 아래 카드·표에서만 고르고, 고르는 버튼이 곧 실행이다.
  - 제목 줄: 키워드 `사건 열기`, 아래에 "클레임이 있는 배치 N개 중 회수 기준(R2) 이상 N개" 한 문장, 오른쪽 끝에 `적용일` 입력.
  - 왼쪽 2/3: 회수 기준 이상 배치를 큰 카드(2칸)로 보인다. 배치 번호, `기준 초과` 배지, 제품·생산일·QC, 불량률(`text-5xl` 빨강), 기준선 막대(배치 카드와 같은 막대), 클레임·확정 불량·생산 수량, `이 배치로 사건 열기` 버튼. 버튼은 모두 남색 외곽선이고, 마우스를 올리면 행동 색(`bg-indigo-500 text-white`)으로 채워진다(어느 배치를 먼저 열지 화면이 정하지 않는다).
  - 오른쪽 1/3: `기준 미달 N개 한눈에`(최고 불량률, QC 합격 수, 확정 불량 있음, 클레임 1건뿐 — 서버 값을 세기만 한다)와 `사건을 열면`(진행 단계 4개).
  - 아래: `기준 미달 배치` 표를 펼친 채로 둔다(불량률 높은 순, 불량률은 소수 둘째 자리). 위에 배치 ID 검색 칸, 줄 끝에 마우스를 올리면 보이는 `사건 열기` 버튼.
  - 사건을 열 수 없는 역할: 제목 문장 끝에 "이 역할은 사건을 열 수 없습니다", 적용일과 모든 열기 버튼을 숨긴다.
- 역할을 바꾸면 보이는 액션 버튼이 달라진다. 화면 구성은 같다.

**연결망 (React Flow, `@xyflow/react`)**
- 3열 고정 배치: 원료 로트 → 배치 → 고객. 자동 배치·물리 효과는 쓰지 않는다 (열 때마다 같은 모양).
- 노드 테두리 색 = 상태의 시맨틱 색상. 노드 안에 ID와 상태 글자.
- 선 모양 = 확인 수준: 실선 = 확인·회신확인, 점선 = 미확인·확인요청중, 옅은 회색 = 영향없음.
- 클레임은 노드로 그리지 않고 배치 → 고객 선 위에 "건수, 수량"으로 올린다.
- 노드나 선을 누르면 옆 패널에 속성, 출처, 근거 원본 행이 나온다.
- 확대·이동은 허용하고, 노드 드래그·연결 편집은 끈다.

## 타이포그래피
글꼴은 Pretendard(없으면 시스템 한글 글꼴). 숫자는 `tabular-nums`.

글자 위계 (v11): 크기와 굵기로 "제목 → 값 → 본문 → 이름·보조" 순서가 읽혀야 한다. v10까지는 글자의 93%가 14px·12px, 70%가 보통 굵기라 구역과 값이 구분되지 않았다. ① 박스 키워드는 본문보다 크고 굵다(v13에서 박스 밖으로 옮기며 15px → 16px, `font-semibold` → `font-bold`). ② 값(수량·날짜·건수)은 이름보다 크고 굵다. 이름은 `text-xs` 회색이다. 항목이 두세 개인 곳은 이름을 값 위에 두고 항목을 옆으로 나란히 놓는다. 표와 긴 목록은 그대로 둔다. ③ 목록 한 줄에서는 사람이 읽는 이름(작업 유형)이 먼저 오고, 번호(`T-001`)는 상태 뒤에 작게 둔다. ④ 경고 문장은 핵심(`: ` 또는 ` (` 앞)만 굵게 한다. ⑤ 글자는 `text-xs`(12px)보다 작게 쓰지 않는다(규칙 번호 표시 11px 제외).

| 용도 | 스타일 |
|------|--------|
| 페이지 제목 (사건 ID) | `text-lg font-medium text-neutral-900` |
| 박스 키워드 (카드 제목) | `text-base font-bold text-neutral-900`, 박스 위 바깥. 건수는 키워드 옆에 `text-xs font-normal text-neutral-500` (v13, v11에서는 박스 안 15px) |
| 배치 번호 (배치 카드 제목) | `font-mono text-lg font-semibold text-neutral-900`. 접힌 한 줄에서는 `text-sm font-semibold` (v11) |
| 값 (배치 카드 근거 항목) | `text-base font-semibold tabular-nums text-neutral-900`, 이름은 위에 `text-xs text-neutral-500` (v11) |
| 작업 이름 | `text-[15px] font-semibold text-neutral-900`, 담당·기한 줄은 `text-xs`이고 기한 날짜만 `text-sm font-medium` (v11) |
| 사건 요약 문장 | `text-2xl font-semibold text-neutral-900` |
| 핵심 숫자 (불량률) | 기준 초과: `text-5xl font-semibold tabular-nums text-red-700`. 기준 미달: `text-3xl font-semibold tabular-nums text-neutral-900` |
| 요약 띠 건수 | `text-lg font-semibold tabular-nums` + 시맨틱 색상(0이면 회색). 이름(`text-xs`)과 같은 줄 (v7) |
| 본문 | `text-sm text-neutral-700 leading-relaxed` |
| 표 | `text-sm tabular-nums`, 숫자 열은 오른쪽 정렬 |
| ID (배치·로트·고객) | `font-mono text-sm` |

- 화면 글자는 전부 한국어다. ID와 규칙 번호(R4 등)는 그대로 쓴다.
- 수량은 천 단위 구분 + 단위(EA), 불량률은 소수 한 자리(%), 날짜는 `YYYY-MM-DD`.

## 애니메이션
- 허용: 액션 뒤 바뀐 항목의 배경 강조 1회 (`bg-amber-50` → 투명, 1초).
- 그 외 모든 애니메이션 금지 (등장 효과, 로딩 스켈레톤 흔들림, hover 확대 등). AI 응답 대기 중에는 "AI가 작성 중…" 글자만 표시한다.
