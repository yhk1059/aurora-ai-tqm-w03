# browser-test-scenarios — 브라우저 테스트 시나리오

> 상태: **v1 실행 완료 (2026-11-13)**. Playwright로 TC-00 ~ TC-07을 모두 실행했고 통과했다. 결과와 발견한 점은 맨 아래 "실행 결과".
> 목적: 시연 영상 촬영 전에, 화면에서 **사람이 누르는 순서 그대로** 시연 3건이 통과하는지 확인한다. 서버 로직은 `backend/tests/`(183개)가 이미 검증하므로, 여기서는 화면 조작 → 상태 변화 → 화면 표시가 이어지는지를 본다.
> 단계 번호(1-1, 2-4 등)와 업무 의미는 [`demo-scenarios.md`](demo-scenarios.md)를 따른다. 여기에는 화면 조작과 확인 항목만 적는다.
> 기대 값 출처: 따로 표시가 없으면 [도출: 임시 DB에서 `scenarios/demo*.json`을 API로 실행한 결과, 2026-11-13]. 화면 문구는 [원본: `frontend/src/`]에서 읽었다.
> 입력 출처 표기([원본]/[모의])는 `demo-scenarios.md`와 같다.

## 0. 실행 환경

| 항목 | 값 |
|---|---|
| 대상 | 배포본과 같은 구성: FastAPI가 `frontend/dist`를 서빙 (포트 8000). 실행 전 `npm run build`로 `dist`를 새로 만든다 |
| DB | 테스트 전용 파일을 쓴다 (`W03_DB_PATH`로 지정). `data/w03.sqlite`는 건드리지 않는다 |
| 화면 크기 | 1440 × 900 (영상 촬영과 같은 크기) |
| AI | TC-01 ~ TC-04는 AI 없이도 통과해야 한다. AI 확인은 TC-07에 모았다 (`.env`에 키가 있을 때만) |
| 도구 | Playwright 1.65.1 (Python, `.venv`) + Chromium. 코드: `w03_system/e2e/` |

**공통 조작 규칙**
- 각 TC는 상단 바 `초기화` 메뉴에서 출발 상태를 골라 `초기화 실행`으로 시작한다.
- 액션 폼의 `적용일`은 기본값이 "사건의 현재 적용일"이다. **단계마다 표의 적용일로 바꿔 넣는다.**
- 모의 입력은 폼의 `예시` 줄에서 고른다. 예시는 폼만 채우고, 실행은 `… 실행` 버튼으로 한다.
- 역할은 상단 바 선택 상자로 바꾼다: `품질 담당자` / `품질위원회` / `SCM`.
- 위원회 결정·재공급 계획 결정은 확인 창이 열리고 `결정 실행`으로 실행한다.

**공통 확인 (모든 단계 뒤)**
- 상단의 빨간 오류 줄이 없다. 브라우저 콘솔 오류가 없다. `/api/` 응답에 4xx·5xx가 없다 (일부러 실패시키는 단계 제외).
- `방금 바뀐 것` 카드가 방금 실행한 액션의 변화를 보인다.
