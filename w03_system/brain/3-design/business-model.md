## 1. 한눈에 보기

```
[원료 로트] ──투입──▶ [배치] ──출하──▶ [고객]
     │                  │  ▲               ▲
     │                  │  └──클레임───────┘
     ▼                  ▼
          [사건]  ◀── 이벤트(클레임·보도·회신·위원회 결과)
            │
            ├─▶ 결정 1: 회수 범위   (품질위원회)
            │        └─ 결과가 상태로 남음 ─┐
            ├─▶ 결정 2: 재공급 순서 (SCM, 영업 확인) ◀─┘
            └─▶ 작업 (확인 요청·고객 안내·재공급 요청·출하 경위 확인)
```

사건 하나가 신호(이벤트)를 모은다. 그 신호로 결정 1을 하고, **결정 1의 결과 상태가 결정 2의 입력이 된다.** 근본 원인 "엇갈린 신호를 결정으로 연결하는 주인이 없다"에 대한 직접 대응이다.

## 4. 상태

### 4-1. 배치 판정 상태
```
정상(사건 밖) ──(로트 공유, R4)──▶ 관찰 ◀──(새 클레임: 미확정이든 확정이든)── 관찰해제
                                    │  └──(90일 무클레임 AND 미확정 클레임 없음, R6·R6-1)──▶ 관찰해제
                                    │
                                    └─(확정 클레임으로 재계산한 불량률 ≥ 10%, R7)─▶ 기준초과(미상신)

기준초과(미상신) ─▶ 상신중 ─┬─ 승인 ──▶ 회수진행
                            ├─ 조건부 ─▶ 부분회수 ─(그 배치에 미확인·확인요청중 관계가 없음)─▶ 회수진행
                            └─ 거절 ──▶ 조사계속 ─(새 확정 클레임 / 조사 회신)─▶ 재상신 후보 → 상신중
```
- `정상`은 사건에 묶이지 않은 배치만 쓴다. 관찰이 풀린 배치는 **`관찰해제`** 로 구분한다(사건에 계속 묶여 있고, 새 클레임이 오면 `관찰`로 돌아간다).
- 기준일 초기 상태: 보류 배치 2개 = **기준초과(미상신)** [가정 A-05]. 합격 배치 2개 = 정상 → 사건 개시 시 **관찰**로 전환(R4) → 마지막 출하 후 120·128일 무클레임이므로 **즉시 해제 조건 충족 → 관찰해제**(R6). 해제된 배치도 사건에는 묶여 있어, 늦은 클레임이 오면 R7이 다시 적용된다.

### 4-2. 고객 영향 상태 (= `SHIPPED_TO` 관계의 확인 수준)
`확인(출하기록)` / `미확인(클레임만)` → `확인요청중` → `회신확인` 또는 `영향없음`
- 출하처 확인 작업(T-02)이 만들어지면 `미확인` → `확인요청중`이 된다. "확인 불가" 회신이면 `확인요청중`으로 남는다. 작업은 고객당 하나이고 그 고객의 미확인 줄 전부를 `TARGETS`로 가리킨다.
- `영향없음`이 되어도 관계 줄을 지우지 않는다. "확인했더니 아니었다"는 이력을 남기기 위해서다.
- 회수·재공급 대상 = 확인 수준이 `확인` 또는 `회신확인`인 줄만.

### 4-3. 작업 상태
`열림` → `회신받음` → `완료` (회신이 오면 시스템이 규칙을 다시 돌린다)
- 기한 = 작업 생성 적용일 + 7일. "확인 불가" 회신이면 회신 적용일 + 7일로 연장한다 [가정 A-17].

### 4-4. 재공급 계획 상태
`초안` → `확정` 또는 `기각` (SCM 결정) / `초안` → `대체됨` (승인 전에 새 버전이 만들어질 때, 시스템). 승인 대기 `초안`은 항상 최신 버전 하나뿐이다. `기각`이면 이전 확정 버전이 유효 계획으로 남는다. 영업 임원 확인 대기는 상태가 아니라 열린 T-05 작업과 경고로 보인다. 입력이 바뀌면(회수 범위·영업 회신) 기존 버전은 그대로 두고 **새 버전을 `초안`으로 만들어** 재계산한다. 버전끼리 비교해 변경 전후 차이를 보인다.

### 4-5. 사건 상태와 현재 적용일
- **현재 적용일:** 사건이 가진 "오늘". 사건 개시일(2026-07-01)에서 시작하고, 이벤트를 입력하면 그 적용일로 전진한다. 실제 시계는 쓰지 않는다(재현성). R6·R6-1의 90일, 미상신 경과일, 작업 기한은 모두 이 날짜로 계산한다.
- **사건 상태:** 저장하지 않고 배치·계획 상태에서 도출한다.

| 사건 상태 | 도출 조건 |
|---|---|
| 열림 | `기준초과(미상신)` 배치가 있고 아직 상신 전 |
| 관찰중 | 묶인 배치가 모두 `관찰` 또는 `관찰해제` (회수 대상 아님). 다른 배치로 연 사건이 "회수 대상 아님"으로 머무는 경우 |
| 판정중 | `상신중` 또는 `조사계속` 배치가 있음 |
| 회수진행 | `부분회수` 또는 `회수진행` 배치가 있고, 확정된 재공급 계획이 없거나 승인 대기 중인 `초안`이 있음 |
| 복구계획확정 | `확정` 버전이 있고 승인 대기 중인 `초안`이 없음 |

### 4-6. 클레임 상태
`접수` → `조사중` → `확정` 또는 `기각`
- 원본 `qc_claims_cv.status`(접수 / 조사중 / 확정 / 종결)와 `defect_confirmed`를 그대로 싣는다. `종결`이면서 불량 확정이 아니면 `기각`으로 본다. 원본 165건 = 확정 45, 종결·불량 확정 19, 종결·미확정 29, 조사중 38, 접수 34 [원본]. 이번 사건의 45건은 모두 `확정`이다.
- **미확정 클레임** = 불량 확정이 아니고 상태가 `접수` 또는 `조사중`인 클레임.

## 5. 판단 규칙

| ID | 규칙 | 근거 |
|---|---|---|
| R1 | 불량률 = 확정 클레임 수량 합 ÷ **생산 수량**. 출하 기준 값은 참고로 표시. "확정" = `defect_confirmed`가 참인 클레임(상태가 `종결`이어도 포함) | `calculation_definitions` §1.9, decisions |
| R2 | 회수 대상 = 확정 불량 있음 **AND** 불량률 ≥ 10% → 위원회 안건 생성 | `quality_policy_cv` |
| R3 | 언론 보도는 판정을 바꾸지 않는다. 재검토 기록과 "결론 유지 근거"를 남긴다 | `quality_policy_cv` |
| R4 | **[확장]** **클레임에 적힌 원료 로트**(`qc_claims_cv.lot_id`) = 기점 로트. 기점 로트를 쓴 다른 배치 → 사건에 묶고 `관찰`. 배치의 다른 투입 로트는 따라가지 않는다 | decisions(필수 확장, 온톨로지 쟁점 6) |
| R5 | **[확장]** QC `보류` 배치에 출하 기록 있음 → 경고 + 생산·물류에 "출하 경위 확인" 작업 | 인터뷰 1차 |
| R5-1 | **[확장]** 기점 로트의 입고검사 결과가 `보류`인데 **검사일 이후 생산된 배치에 투입**됨 → 경고 "투입 경위 확인 필요" + R5 작업(T-01)의 근거에 추가. **경고만** 하고 사건을 자동으로 열지 않는다. 투입일이 입고일보다 빠른 배치는 "원본 기록 충돌"로 따로 표시한다 | A-15. 원본 날짜·물량 한계(A05 §4) 때문에 판정 근거로 쓰지 않는다 |
| R6 | 관찰 해제: **마지막 출하일 기준 90일** 무클레임이면 `관찰해제` (근거와 함께 자동 해제) | 과거 클레임은 모두 첫 출하 후 81일 이내(p95 75일) [도출]. A-07 |
| R6-1 | 재관찰(해제 후 클레임으로 관찰 복귀): **마지막 클레임 확정일 기준 90일** 무클레임이면 해제 | A-12 |
| R6-2 | 미확정 클레임이 걸려 있는 배치는 해제하지 않는다. `관찰해제` 배치에 미확정 클레임이 오면 `관찰`로 돌아간다. 그 클레임이 `기각`되면 원래 기준(R6 또는 R6-1)으로 다시 판단한다 | A-16 |
| R7 | 사건에 묶인 배치(관찰·해제 포함)에 확정 클레임 → R1·R2 재계산 | decisions |
| R7-1 | 사건에 묶인 배치에 **미확정 클레임** → 사건에 추가하고 **"확정 시 불량률"**((확정 + 미확정 수량) ÷ 생산 수량)을 참고값으로 표시. **판정은 바꾸지 않는다.** 그 값이 10% 이상이면 "확정 시 기준 초과 예상" 경고 | A-16. 정책상 회수 요건은 확정 불량이다(`quality_policy_cv`) |
| R8 | 클레임 고객이 출하처에 없음 → 고객 영향 `미확인` + 물류 확인 요청 + 해당 고객 회수·재공급 보류 | 범위 규칙 ④, A-02 |
| R9 | 위원회 결과 처리: **승인** → `회수진행` + 고객 안내 후보 제시 + 재공급 요청 / **조건부** → 부분 회수(확인 고객만 먼저, 미확인은 물류 회신 후) / **거절** → 사유 필수 입력 + `조사계속` + 원인 조사 작업 생성. 새 확정 클레임 또는 조사 회신이 오면 재상신 후보 | A-08, A-09 |
| R9-1 | 고객 안내 범위: 시스템은 후보(회수 배치 고객 + 관찰·해제 배치 고객을 구분 표시)만 제시하고, **영업이 확인 작업으로 대상을 결정**한다 | 인터뷰 2차. 부서 영향 지점(영업) |
| R10 | 재공급 순서 = ① 확인 고객 → ② 회수 수량 → ③ 매출 비중. 여유 능력 월 약 1.5만 EA 안에서 배분. 영업 임원 회신이 순서를 바꿀 수 있음. 배분 = 순위대로 한 고객씩 채우고, 완료 월 = 누적 수량 ÷ 월 여유 능력을 올림(현재 적용일의 달이 1번째 달). 우선 공급 요청이 여러 건이면 회신 순서대로 앞에 둔다 | A-03, A-04 |

### 8-2. 객체 타입 (11개)
정의와 출처는 §2 표를 따른다: 사건, 원료 로트, 배치, 클레임, 출하 기록, 고객, 이벤트, 결정, 작업, 재공급 계획, 재공급 계획 줄.
- **이력은 객체 타입이 아니다.** 액션이 실행된 기록이다(§8-5).
- **이벤트는 밖에서 온 신호**(클레임 접수, 보도, 회신 원문)만 담는다. 승인·거절은 결정 객체로 남고, 입력 행위는 액션이다.

|---|---|---|---|---|
| 사건 열기 | 품질 담당자 | 배치 1개 | 그 배치에 클레임이 있음 | 사건 생성, 배치 묶음(R4), 경고(R5, R5-1), 미확인 관계(R8), 작업 T-01·T-02 |
| 클레임 등록 | 품질 담당자 | 배치, 고객, 수량, 날짜, 상태(접수 / 확정) | 배치가 사건에 묶여 있음 | 클레임·이벤트 생성 → 미확정이면 R7-1·R6-2, 확정이면 판정 재계산(R7) |
| 클레임 판정 반영 | 품질 담당자 | 클레임, 확정 / 기각 | 클레임이 미확정 | 클레임 상태 → 확정이면 판정 재계산(R7), 기각이면 해제 조건 재판단(R6-2) |
| 보도 등록 | 품질 담당자 | 보도 내용, 발생일 | — | 이벤트 + 재검토 기록만 (R3, 상태 변화 없음) |
| 안건 상신 | 품질 담당자 | 배치, AI 안건 요약 | 판정 상태 = 기준초과 또는 재상신 후보 | 배치 → 상신중 |
| 위원회 결정 입력 | 품질위원회 ([원본] `approval_authority_policy`) | 승인 / 조건부 / 거절, 사유 | 배치 = 상신중. 거절은 사유 필수 | 결정 생성, 배치 → 회수진행 / 부분회수 / 조사계속, 작업 생성 (R9) |
| 회신 반영 | 품질 담당자 | 작업, 회신 문장, AI가 고른 회신 결과 | 작업 = 열림. 결과가 아래 허용 목록에 있음 | 이벤트 생성, 작업 상태, 그리고 `TARGETS` 대상에 아래 표의 효과 |
| 재공급 계획 결정 입력 | SCM ([가정 A-01]) | 승인 / 거절, 근거 | 계획 = 초안, 출고 조건 충족(R11). 열린 T-05가 있어도 승인할 수 있고 경고를 보인다. 열린 T-01이 있으면 경고를 보이고 승인에 근거가 필수다(R11-1) | 결정 생성, 계획 → 확정 또는 기각(이전 확정 버전 유지) |
| 초기화 | 누구나 | — | — | 기준일 초기 상태(S0)로 복원 |

**회신 반영: 작업 유형별 허용 결과와 효과**
| 작업 유형 | 허용 결과 | 효과 |
|---|---|---|
| 출하 경위 확인 (생산·물류, T-01) | 경위 확인됨 / 확인 불가 | 작업 완료 또는 기한 연장 (판정은 바꾸지 않음). 작업이 열려 있는 동안 재공급 계획 초안에 경고가 붙고 승인에 근거가 필수다(R11-1) |
| 출하처 확인 (물류, T-02) | 출하 확인 / 영향없음 / 확인 불가 | `SHIPPED_TO` 확인 수준 → `회신확인` / `영향없음` / 유지 + 기한 연장 |
| 안내 대상 결정 (영업, T-03) | 회수 배치 고객만 / 관찰·해제 배치 고객 포함 | 안내 대상 기록 (R9-1) |
| 수주 급감 확인 (영업 임원, T-05) | 순서 유지 / 우선 공급 요청 | 유지 또는 재공급 계획 새 버전(초안) |
| 원인 조사 (품질·생산, T-06) | 원인 확인 / 원인 미확인 | 배치 → 재상신 후보 또는 조사계속 유지 |
| 재공급 요청 (SCM, T-04) | (회신 없음) | SCM이 재공급 계획 결정을 입력하면 자동 완료 |
| 결과 통보 (영업 임원) | 확인함 | 작업 완료. SCM이 계획을 기각하면 만들어진다 |

- AI는 회신 문장을 허용 결과 중 하나로 분류하고 근거 문장을 뽑는다. 맞는 것이 없으면 "해석 불가, 담당자 확인"으로 멈춘다.
- **AI는 어떤 액션도 직접 실행하지 않는다.** 액션의 입력(요약, 분류 결과, 초안)만 준비하고, 실행은 사람이 한다 (R12).

**시스템 자동 처리** (사람 액션이나 적용일 전진에 따라 실행)
| 자동 처리 | 언제 | 바꾸는 것 |
|---|---|---|
| 관찰 해제 | 현재 적용일이 전진할 때, 클레임이 기각될 때 | 배치 관찰 → 관찰해제 (R6, R6-1). 미확정 클레임이 있으면 하지 않음 (R6-2) |
| 관찰 복귀 | `관찰해제` 배치에 클레임이 등록될 때 | 배치 관찰해제 → 관찰 (R6-2, R7) |
| 판정 재계산 | 클레임이 등록될 때 | 배치 판정 상태 (R1, R2, R7) |
| 부분회수 완료 판정 | `SHIPPED_TO` 확인 수준이 바뀔 때 | 그 배치에 `미확인`·`확인요청중` 관계가 없으면 배치 부분회수 → 회수진행 |
| 재공급 계획 재계산 | 회수 범위나 영업 임원 회신이 바뀔 때 | 계획 새 버전(초안) (R10, R10-2) |
| 수주 급감 확인 요청 | 계획 초안이 만들어질 때 (같은 고객에 열렸거나 회신된 작업이 이미 있으면 다시 만들지 않음) | 작업 생성 (R10-1) |

**액션 기록(이력):** 모든 액션·자동 처리는 실행자, 적용일, 입력, 바뀐 대상의 이전→이후 값, 원인(이벤트·결정·규칙)을 남긴다. 기록을 순서대로 다시 실행하면 같은 상태가 나온다(초기화 후 재현, 시연 2의 출발 상태 만들기).

**규칙의 자리**
| 자리 | 규칙 |
|---|---|
| 파생 속성 | R1, R2(기준 초과 여부), R6·R6-1(해제 예정일), R10-1(급감 신호), R11(충족 여부) |
| 액션의 효과 | R4, R5, R5-1, R8 (사건 열기), R3 (보도 등록), R9, R9-1 (위원회 결정·회신 반영) |
| 액션의 전제 조건 | R11 (계획 승인), 거절 사유 필수 (A-09), 열린 T-01이 있을 때 승인 근거 필수 (R11-1, A-18) |
| 자동 처리 | R6, R6-1, R6-2, R7, R7-1, R10, R10-1, R10-2 |
| 권한 원칙 | R12 |

### 8-6. 규칙은 관계를 따라간다
| 규칙 | 온톨로지 위의 동작 |
|---|---|
| R4 (확장) | 사건 배치의 클레임 → `CLAIMED_LOT` → 기점 로트 → `USED_IN` → 다른 배치 → `PART_OF` 추가 |
| R5 (확장) | 배치 QC = 보류 AND `SHIPPED_TO` 존재 → 경고 + 작업 |
| R5-1 (확장) | 기점 로트 입고검사 = 보류 AND `USED_IN` 배치의 생산일 > 검사일 → 경고 + T-01 근거 추가 |
| R8 | `CLAIMED_BY` 고객 ∉ `SHIPPED_TO(확인)` 고객 → `SHIPPED_TO(미확인)` 생성 + 확인 요청 작업(`TARGETS` = 그 줄) |
| R9 부분 회수 | 회수 대상 = `SHIPPED_TO` 중 확인 수준 `확인`·`회신확인`인 고객만 |
| R10 | 회수 범위의 `SHIPPED_TO` 수량 → 고객별 회수량 → 계획 줄 `RESUPPLIES` 순서 |
| R11-1 (확장) | 작업 유형 = 출하 경위 확인 AND 상태 = 열림 → 재공급 계획 초안에 경고 + 승인 액션의 근거 필수 |
| 상태 전이 | 정의된 전이표에 있는 전이만 허용. 전이는 액션·자동 처리로만 일어나고, 모두 액션 기록에 남는다 |

### 8-7. 실제 사용 사례 (심사 증거로 보여줄 것)
1. **사건 범위 조회:** 로트 1개에서 시작해 배치 4개 → 고객 → 클레임까지 한 번에 따라간다.
2. **확인 수준이 판단을 바꿈:** 미확인 관계(C-105)가 부분 회수 범위에서 빠지고, 회신 후 들어온다.
3. **재판단:** 새 이벤트가 오면 관계를 다시 따라가 판단을 갱신하고, 무엇이 바뀌었는지 액션 기록으로 보인다.
4. **연결망 화면:** 사건 화면에 로트·배치·고객·클레임 연결망을 상태 색깔과 출처 표시로 보여준다.

### 8-8. 범위
- 인스턴스는 **사건 1건에 필요한 객체만** 적재한다 (범위 규칙 ①). 회사 전체 데이터를 넣지 않는다.
- 정의는 일반적으로 써서, 다른 사건(배치)을 입력해도 같은 정의로 돌아가게 한다.
